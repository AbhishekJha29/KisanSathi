# KisanSathi - Bug Log Document

This log tracks all architectural defects, regression bugs, security vulnerabilities, accessibility issues, and validation edge cases identified and resolved during the project lifecycle, including historical fixes and the comprehensive testing/hardening pass.

| Bug ID | Found in phase | Description | Severity | How it was found | Prompt used to fix | Status |
| :--- | :--- | :--- | :--- | :--- | :--- | :--- |
| BUG-001 | Initial Database Seeding | Seed failed with `"table crops has no column named expected_yield"` because an old database file (`kisansathi.db`) retained an outdated schema lacking the new column. | High | Database initialization script failure during `python -m backend.seed`. | "Delete the existing SQLite database file and re-run seed.py to ensure the schema migration creates the expected_yield column." | Fixed |
| BUG-002 | Data Integrity Audit | Potato seed data (`backend/data/crops/potato.json`) used the soil `"sandy loam"`, which was not present in the allowed soil list (`sandy`, `loamy`, `clayey`, `black`, `red`, `alluvial`), causing false soil mismatch warnings and test failures. | Medium | Agronomic soil constraint validation and database integrity checks. | "Normalize unallowed soil types across seed JSONs to canonical allowed soils and enforce seed schema validation." | Fixed |
| BUG-003 | Frontend Build & Typecheck | `HomePage.tsx` referenced an undefined variable `language` inside the crops error retry banner block, causing a TypeScript compilation error (`TS2304: Cannot find name 'language'`). | High | TypeScript static typecheck (`npm run build` / `tsc`). | "Add language to HomePageProps interface, pass language from App.tsx, and consume it inside the crop loading error block." | Fixed |
| BUG-004 | Security Hardening (Task 1) | Unmatched API routes (e.g. `POST /api/nonexistent`) returned HTTP 405 Method Not Allowed instead of HTTP 404 Not Found JSON because Flask's SPA `catch_all_routes` was configured with `methods=['GET']` only. | Medium | Automated route testing and test client inspection in `test_security.py`. | "Add all standard HTTP methods (POST, PUT, DELETE, PATCH, HEAD, OPTIONS) to catch_all_routes and abort(404) immediately if the requested path starts with api/." | Fixed |
| BUG-005 | Security Hardening (Task 1) | Path traversal vulnerability and SPA fallback loop in static file serving (`_serve_dist_file` and `handle_not_found`). Requests with encoded `..`, backslashes, or non-existent static assets with extensions recursively served `index.html`. | High | Static file audit and path traversal test cases in `test_security.py`. | "Sanitize static paths using urllib.parse.unquote, reject null bytes and Windows drive letters, enforce Path.resolve().relative_to(dist_dir), and return 404 for missing static files with extensions." | Fixed |
| BUG-006 | Input Validation (Task 2) | Validation bypass on optional fields (`district`, `block`, `farmerName`) where whitespace-only strings (e.g. `"   "`) or explicit `null` values bypassed field validation and reached database queries. | Medium | Parametrized validation testing in `test_validation_edge_cases.py`. | "Update validation.py to trim string inputs, reject null and whitespace-only strings for required and optional text fields, and convert empty strings to None." | Fixed |
| BUG-007 | Frontend Hardening (Task 4) | `ErrorBoundary` component (`frontend/src/components/ErrorBoundary.tsx`) had an empty `componentDidCatch` lifecycle implementation, silently swallowing React component rendering crashes without console logging. | Medium | Code audit of frontend error boundaries in Task 4. | "Add console.error(error, errorInfo) inside componentDidCatch in ErrorBoundary.tsx while maintaining bilingual error UI." | Fixed |
| BUG-008 | Frontend Hardening (Task 4) | Form in `GetAdvicePage.tsx` lacked client-side boundary validation for `landSize` (allowing negative or >10000 numbers to be sent), and lacked character limits on text inputs (`district`, `block`). | Medium | Manual form validation review and accessibility review in Task 4. | "Implement client-side form validation before submission in GetAdvicePage, enforce 0 < landSize <= 10000, add maxLength={100} to inputs, and display localized error messages." | Fixed |
| BUG-009 | Accessibility (Task 5) | Form inputs in `GetAdvicePage.tsx` lacked programmatic accessibility associations: inputs missing `aria-describedby` linking to error containers, missing `aria-invalid`, and error messages missing `role="alert"`. | Low | Accessibility compliance audit against WCAG 2.1 AA in Task 5. | "Connect form inputs to error message spans using aria-describedby, set aria-invalid based on error state, and mark error text with role='alert'." | Fixed |
| BUG-010 | Accessibility (Task 5) | Language toggle in `Header.tsx` updated UI strings and localStorage but failed to update `document.documentElement.lang`, leaving the DOM language attribute permanently as `"en"` even when Hindi was active. | Low | Accessibility DOM inspection in Task 5. | "Add a useEffect hook in App.tsx syncing document.documentElement.lang with the active language state ('en' or 'hi')." | Fixed |
| BUG-011 | Accessibility (Task 5) | Dialog modals (`VoiceAssistantModal`, `CultivationGuideModal`, `RequestCropModal`, `FarmerProfileModal`) lacked keyboard focus trapping, did not close when the `Escape` key was pressed, and failed to return focus to the triggering element upon dismissal. | Medium | Keyboard accessibility evaluation in Task 5. | "Create and apply a reusable useModalA11y hook to trap keyboard focus inside open modals, handle Escape key dismissal, and restore focus to trigger buttons." | Fixed |
| BUG-012 | Performance (Task 6) | Dropdown options (`/api/options`) were fetched repeatedly across multiple component mount cycles rather than being cached in memory on the client. | Low | Network waterfall analysis and client API audit in Task 6. | "Add an in-memory cache for getOptions() in frontend/src/api/client.ts to ensure options are fetched only once per browser page lifecycle." | Fixed |
| BUG-013 | Code Quality (Task 4) | Outdated comment in `HomePage.tsx` referenced `"Gujarat"` state specific data, which conflicted with the nationwide multi-state agricultural data model. | Low | Code search for stale state references across `frontend/src/`. | "Remove obsolete Gujarat references and align comments with the national multi-state agricultural coverage." | Fixed |
| BUG-014 | Code Quality (Task 6) | Duplicate import statements for `HomePage`, `GetAdvicePage`, and `ResultsPage` in `frontend/src/App.tsx`. | Low | Code inspection following component reorganization. | "Remove redundant duplicate import lines from App.tsx." | Fixed |
